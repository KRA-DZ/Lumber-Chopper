# Работа с Lumber-Chopper

Цель: минимально достаточные чтение, изменения и проверки с сохранением корректности. Общение с пользователем — по-русски, кратко: что изменено, что проверено, что мешает завершению.

## Контекст и чтение

- Карта проекта и команды: [docs/PROJECT-MAP.md](docs/PROJECT-MAP.md). Использовать её как указатель, затем проверять актуальный затронутый код.
- Начинать с `git status --short`, поиска `rg` и небольших фрагментов нужных файлов. Не перечитывать всю архитектуру и историю разработки при каждом обновлении.
- Расширять чтение на вызывающий код, зависимости и тесты только при необходимости. Не угадывать контракт функции ради экономии токенов.
- Не загружать содержимое PNG, аудио, крупных манифестов, тайлмапов, `vendor/` или `dist/`, если задача этого не требует. При работе с графикой смотреть только нужные изображения/метаданные.
- Независимые поиски и чтения объединять; не выполнять полный обход репозитория повторно без причины.

## Архитектура и изменения

- Основная версия — Phaser 3 / JavaScript ES modules, вход `phaser.html`. `index.html` — версия Canvas для сравнения; менять её только в рамках поставленной задачи.
- Сохранять разделение: `game/` — модель и игровые команды без Phaser/DOM; `phaser/` — отображение, ввод, камера, интерфейс и звук. Общая экономика и лесозаготовка также находятся в корне.
- Не переносить проект в новую структуру и не мигрировать на TypeScript ради соответствия шаблону. Отдельный модуль нужен самостоятельной системе; небольшие связанные функции могут оставаться вместе.
- Править целевые функции и данные патчами. Не переписывать файл целиком, не форматировать посторонние участки, не включать несвязанный рефакторинг.
- Новую механику отделять от общего `update()`; изменения ресурсов выполнять в модели, анимациям оставлять визуальную обратную связь.
- Ключевые настройки баланса и новые поля состояния пояснять короткими комментариями. Не менять экономику и соседние механики без связи с задачей.

## Phaser и пиксельная графика

- При изменении конфигурации/камеры сохранять `pixelArt: true`, `roundPixels: true`, отсутствие сглаживания. Эти настройки не заменяют качественные ассеты и корректное масштабирование.
- Использовать существующий атлас, PNG и одобренный стиль. Новые изображения — PNG с настоящим прозрачным alpha-каналом, без белого ореола; не считать белый фон прозрачностью.
- Общие Phaser-анимации регистрировать один раз после загрузки текстур, обычно в `create()` загрузочной сцены. Не дублировать регистрацию в каждом персонаже и не переделывать существующую систему кадров без необходимости.
- Не создавать текстуры/анимации каждый кадр. Сохранять ограниченные кеши, лимиты эффектов/врагов, отсечение невидимых объектов и бюджет поиска пути.
- Учитывать мышь и тач; не ухудшать управление и паузу. Не обещать FPS на реальных устройствах по одним headless-проверкам.

## Проверки и Git

- Выбирать тесты по изменённому поведению. Добавлять регрессионный тест для существенного риска/исправленного бага; не писать тесты, лишь повторяющие реализацию.
- Браузер проверять только там, где важны отрисовка, ввод или интеграция. После успеха не повторять всю игру без нового изменения, сбоя или обоснованного риска.
- Для изменений только документации достаточно проверки diff и ссылок/путей; игру не запускать. Для изменений сборки/исполняемого кода при необходимости выполнить `npm run build`.
- Коммит — законченное логическое изменение с относящимися к нему тестами/документацией. Короткие сообщения Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:` и т. п.
- Отправлять в согласованную пользователем ветку в рамках авторизованной задачи. Не делать force-push и не затрагивать чужие изменения. Об успешной отправке сообщать после проверки удалённого коммита.
- Если среда/сеть недоступна, сообщать точную блокировку; не выдавать план, локальный коммит или ожидание за выполненный push.

## Действующие решения игры

- При новой загрузке прогресс сбрасывается; сохранения не включать без отдельной задачи.
- Смотритель появляется каждую ночь и неуязвим. Налёты и глобальная погоня малых врагов — с заката каждой пятой ночи; в обычные сутки малые враги привязаны к регионам.
- Эти решения — текущая база, а не запрет на будущие согласованные изменения. Обновлять карту проекта при существенном изменении расположения или ответственности модулей.
