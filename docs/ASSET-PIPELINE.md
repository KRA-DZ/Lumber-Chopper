# От сгенерированного листа к PNG в Phaser

Рабочий набор уже находится в `src/assets/`. [Исходник на белом фоне](../art/source/camp-sheet.png), [каталог отдельных PNG](assets-preview.html), [лагерь в игре](png-assets-camp.png), [дом торговца в игре](png-assets-merchant.png).

## Подготовка и публикация

Нужны Python 3.10+, Pillow и установленный Git. Для самой игры Python не нужен.

```sh
python -m pip install -r requirements-assets.txt
python scripts/prepare_assets.py art/source/camp-sheet.png --background all --defringe 1
```

Команда создаёт `tent.png`, `shop.png`, `merchant.png`, `spruce.png`, `birch.png`, `campfire.png` и `manifest.json` в `src/assets/`. Манифест хранит исходные размеры/области, контрольную сумму исходника, параметры обработки и ориентировочные точки основания. Он нужен загрузчику игры вместе с шестью PNG.

Для автоматического коммита и отправки **только этих семи файлов**:

```sh
python scripts/prepare_assets.py art/source/camp-sheet.png --background all --defringe 1 --publish
```

`--commit` делает только локальный коммит. Без этих флагов Git не используется. Скрипт использует Git CLI; PyGithub и токен внутри Python-кода не нужны. Автор и доступ к GitHub должны быть настроены обычными средствами Git. Он работает с текущей веткой и её настроенным upstream, без force push. Если есть неотправленные локальные коммиты или удалённая ветка ушла вперёд, сначала нужно синхронизировать ветку: скрипт откажется публиковать постороннюю историю. Другие подготовленные в индексе файлы сохраняются и не входят в asset-коммит. При неизменных результатах повторного коммита/отправки нет. Если push отклонён после создания коммита, локальный коммит остаётся для обычного разрешения ситуации через Git.

Исходный лист лежит в `art/source/`; автоматическая команда публикует только `src/assets/`. Изменённый исходник и изменения кода/настроек можно коммитить обычным способом после просмотра результата.

## Как работает нарезка

На нашем листе просторная сетка 3×2, порядок слева направо по строкам: палатка, дом, торговец, ель, берёза, кострище. Имена назначаются по этому порядку — семантического распознавания «дом/дерево» скрипт не выполняет.

Сначала строится маска фона, затем находятся 8-связные контуры. В режиме `grid` **целые контуры** относятся к ячейке по центру, а отдельные колышки/верёвки объединяются с объектом в той же позиции. Граница строки не обрезает верхушку дерева: реальная граница обрезки идёт по маске объекта. После этого удаляются мелкие случайные пиксели и добавляется прозрачный отступ. Все шесть результатов проверяются до записи; существующие файлы не очищаются заранее.

- `--background edge` — режим по умолчанию: удаляется светлый фон, соединённый с краем листа. Замкнутые белые детали, например кора берёзы, сохраняются. Замкнутые белые просветы между ветвями тоже могут сохраниться.
- `--background all` — удаляется весь близкий к белому цвет, включая замкнутые просветы. Для приложенного листа выбран этот режим: в промпте чистый белый зарезервирован для фона, кора нарисована оттенками слоновой кости/серого. Для другого рисунка сначала проверьте результат, поскольку настоящий белый внутри объекта здесь тоже станет прозрачным.
- `--tolerance 12` — допустимое отклонение от белого; большее значение может удалить светлые части объекта.
- `--defringe 1` — очищается один тонкий слой почти белого ореола у прозрачной границы. Значение по умолчанию 0; допустимо до 2.
- `--layout components --min-area 16` — строгий режим для шести самостоятельных связных объектов, без отделённых деталей. Если контуров не шесть, будет ошибка вместо неверной нарезки.
- `--columns 2` — для листа в две колонки; `--names tent,shop,...` позволяет задать другой порядок безопасных имён.

Соприкасающиеся объекты, слишком тесная раскладка, размытые падающие тени и белые детали, неотличимые от фона, требуют другого листа или ручной маски. Автоматически восстановить их истинный контур по одному цвету невозможно. Нижняя часть силуэта даёт ориентировочную точку основания; итоговую посадку на карту и масштаб нужно проверить в игре.

## Подключение к текущей игре

`phaser/main.js` загружает шесть изображений и JSON через штатный `preload()`. `phaser/imported-art.js` один раз подгоняет изображения к текущей пиксельной сетке и заменяет нужные спрайты перед упаковкой общего атласа. Файлы в `src/assets/` остаются в разрешении экспорта. Фильтрация — NEAREST.

| Файл                      | Использование                                                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `tent.png`                | Палатка лагеря со второго этапа; каркас подогнан к размеру нового полотна.                                        |
| `shop.png`                | Деревянный дом загадочного торговца в Сумеречной чаще. Собственная хижина игрока остаётся отдельной постройкой.   |
| `merchant.png`            | Загадочный торговец. Поставляется одна статичная поза; полноценные новые жесты потребуют отдельного листа кадров. |
| `spruce.png`, `birch.png` | Деревья по карте, включая молодой и увеличенный варианты. Маски нажатия и кадры ветра создаются из новых растров. |
| `campfire.png`            | Экспорт без огня. При розжиге игра накладывает существующие кадры пламени на новый каменный обод.                 |

Объекты по-прежнему сортируются по Y их основания. Коллизии и A* используют уже существующие круглые стволы и скруглённые основания: Arcade Physics не включается параллельно. Изометрическая перспектива изображений совместима с текущей 2D-картой; эта замена не перестраивает координатную сетку мира.

Код-пример с `physics.add.existing()` потребовал бы включить физический плагин и добавить реальные collider-связи с игроком. В нашем проекте это дублировало бы готовую навигацию. Сортировать статичные объекты в отдельной группе каждый кадр тоже не нужно: текущие Phaser Images/Sprites уже получают глубину по основанию, а герой/NPC обновляют её при движении.

Прежняя Canvas-версия остаётся в `index.html`. Для проверки прежнего оформления лагеря и деревьев Phaser доступен адрес `phaser.html?art=procedural`; дополнительного копирования игры нет. Этот параметр отключает исходные шесть импортированных PNG, но новые общие наборы биомов и людей продолжают использоваться в обоих режимах. Полная прежняя Canvas-версия остаётся в `index.html`. Обычный `phaser.html` использует все утверждённые PNG.

## Нагрузка, сборка и проверки

PNG суммарно занимают около 0.93 MB. Полная статическая сборка — около 2.41 MB без сжатия. Исходный большой лист, каталог и Python в сборку не входят. Атлас остаётся ограниченным 2048×2048. После упаковки удаляются шесть исходных GPU-текстур; декодированные изображения сохраняются для перезапуска сцены (около 3 MB RGBA), чтобы не загружать их повторно. Нарезка и анализ контуров выполняются только Python-скриптом, не во время игры.

```sh
python -m unittest discover -s tests -p assets_pipeline_test.py
npm test
npm run build
python tests/imported_assets_smoke.py
python tests/phaser_smoke.py
```

Python-тесты проверяют сохранение замкнутой белой коры, контуры, пересекающие условную границу строки, отделённые колышки, отказ при неверном количестве объектов, воспроизводимость и настоящую публикацию в локальный bare Git-репозиторий с сохранением чужого индекса. Браузерные проверки проходят на WebGL и Canvas: загрузка PNG/атласа, нажатие по прозрачной маске берёзы, добыча, основания анимации костра, дом торговца, перезапуск и возврат к процедурному набору. Это функциональные проверки, не гарантия FPS на физических устройствах.

## Подготовка выбранных людей

`python scripts/prepare_people.py` готовит отдельный лист `src/assets/people/people.png` (1024×1024), манифест и два стартовых портрета по десяти сгенерированным оригиналам. Разбиение задаётся явно для каждой группы; обрезанная поза не импортируется. Герои 2/3 выбираются до создания симуляции; кадры подставляются в существующие анимации, обычный загрузчик освобождает временную GPU-текстуру. У NPC собственные образы вместо перекраски покупателя. Проверки и известное покрытие поз — [CHARACTERS.md](CHARACTERS.md).
