# Нагрузка браузерной версии

Замер от 27 октября 2026, сравнение с `f6fc344`. Это короткий диагностический прогон в headless Chromium с **программным WebGL (SwiftShader)** и мобильным viewport 390×844. Эмуляция размера экрана не воспроизводит процессор, GPU и нагрев настоящего телефона.

В каждом сценарии герой ходит по одной тропе с 40 брёвнами. После одной секунды прогрева собираются три секунды кадров. Измерение `World.step` охватывает симуляцию и подготовку сцены; отрисовка движка/GPU и большая часть обновления нативных анимаций происходят отдельно. Интервал RAF включает ожидание браузерной отрисовки и планировщика. Скриншоты в это время не делаются, другие браузерные тесты одновременно не запускаются.

Числа в таблице — медиана / P95, миллисекунды. P95 означает, что 95% измерений не превышали указанное время.

| Сценарий             | World.step до | World.step после | Интервал RAF после |
| -------------------- | ------------: | ---------------: | -----------------: |
| День, 40 брёвен      |     0.7 / 5.5 |          1 / 2.1 |          16.8 / 50 |
| Дождь, 40 брёвен     |     0.9 / 4.7 |        0.9 / 4.3 |        33.3 / 50.1 |
| Ночь, 40 брёвен      |       1 / 5.3 |        1.2 / 3.9 |        33.3 / 66.7 |
| Ночь, лёгкие эффекты |     0.8 / 2.8 |        0.9 / 4.6 |        33.4 / 66.7 |

Медианная стоимость подготовки кадра после изменения — 0.9–1.2 мс против 0.7–1.0 мс до изменения. Разброс и короткий прогон не позволяют объявить небольшие отличия FPS ускорением или замедлением. У программного WebGL медианный интервал RAF составляет около 33 мс в большинстве сценариев, а встречаются более длинные задержки. **Стабильные 60 FPS этим прогоном не подтверждены**, ни для старой, ни для новой версии. Максимальная задержка после изменения достигала 150 мс; это наблюдение всей браузерной среды, а не измеренная стоимость одного нового эффекта.

Проверяемые границы после доработки:

- Атлас остался 2048×2048: 16 MiB RGBA на копию. Новые кадры не потребовали увеличения текстуры.
- Добавлены три постоянных объекта: два Graphics и одна текстовая метка. В том же сценарии сцена содержит 1132 объекта вместо 1129, текстур — 36 вместо 35. Числа относятся ко всей сцене, включая скрытый декор, а не к количеству видимых вызовов рисования.
- Индикатор прочности один. Подсветка запасов ограничена 8 / 3 в лёгком режиме, эффекты последнего удара — 4, щепки — общим пределом 64.
- Во время сравнения использовалось 12 видимых чанков; исходный кеш ограничен 28. Создавать массив перелётов заново для каждого из 40 переносимых брёвен больше не требуется.
- Серия настоящих рубок проверяет пределы всплывающих надписей/падающих деревьев/частиц. Повторная отрисовка сама по себе не создаёт новые объекты и не изменяет ресурсы.

Эти изменения подходят для текущей браузерной архитектуры и имеют ограниченную стоимость. Следующая проверка плавности — аппаратный Chrome/Firefox на обычном ПК и физические Android/iPhone: несколько минут рубки, дождь, ночной свет, большая ноша, расширенный лагерь. Нужны время кадра, длинные задержки и память после прогрева. Лёгкий режим уже снижает частицы, подсказки и частоту/разрешение ночной маски.

Повторение замера:

```sh
python tests/phaser_performance.py --baseline /path/to/previous-checkout
```

Скрипт сам запускает локальные HTTP-серверы. Флаг `--baseline` необязателен; JSON по умолчанию пишется в `/tmp/lumber-performance.json`. Накладные расходы измерителя существуют только в тесте, в игровую сборку он не входит. [Исходные данные этого прогона](performance-sample.json).

## Крупные регионы: отдельный прогон

После перехода на сетку выполнено такое же сравнение с предыдущей версией `603751c`: мобильный viewport, программный WebGL, 40 брёвен, по 1 с прогрева и 3 с наблюдений. Это стартовый участок и одна тропа, не профиль всей открытой карты.

| Сценарий             | World.step до, медиана / P95 | После, медиана / P95 | RAF после, медиана / P95 |
| -------------------- | ---------------------------: | -------------------: | -----------------------: |
| День                 |                      1 / 6.8 |            0.9 / 5.3 |                50 / 83.3 |
| Дождь                |                    0.8 / 4.1 |            1.1 / 7.1 |              33.4 / 83.4 |
| Ночь                 |                   1.2 / 12.7 |            1.1 / 7.3 |               33.3 / 100 |
| Ночь, лёгкие эффекты |                      1 / 7.2 |           1.3 / 10.3 |               50 / 116.6 |

Атлас снова остался 2048×2048, активных чанков — 12. В сцене стало 297–298 объектов вместо 1132: дальние деревья и декор теперь не держатся нативными объектами постоянно. Текстур в этом сценарии — 38 вместо 36. Медианная подготовка кадра после изменения — 0.9–1.3 мс. Большие колебания RAF сохраняются в обеих версиях; максимальная задержка после изменения — 266.8 мс. Этот короткий прогон **не подтверждает стабильные 60 FPS или ускорение на физических устройствах**.

Отдельная проверка открывает все 25 регионов в одной сессии, возвращается из дальних участков и контролирует менее 170 активных спрайтов деревьев, не больше 4 близких наборов декора и не больше 28 видимых/кешированных чанков. Данные деревьев и коллизий хранятся для открытых участков; проверка ограничений не заменяет длительного замера памяти/FPS на телефоне. ## Ночные противники и 82 бревна — 29 октября 2026

[Измерения новой версии](performance-survival.json) выполнены в headless Chromium с программным WebGL, в мобильном размере экрана. Измеряется весь `World.update` через `Systems.sceneUpdate`, включая шаги модели и представление; прежние отчёты измеряли `World.step`, поэтому напрямую сравнивать CPU-числа между этими методами нельзя.

В сценарии пятой ночи одновременно видимы 82 бревна и четыре противника (Смотритель + три налётчика): 347 объектов сцены, атлас 2048×2048, 12 чанков земли. Медиана времени кода кадра — 1,0 мс, p95 — 4,4 мс; медиана интервала RAF — 50 мс, p95 — 83,3 мс. Программная отрисовка и задержки среды не позволяют обещать 60 FPS на устройствах. Дневной сценарий с 40 брёвнами дал медиану CPU 0,7 мс. Сценарий не измеряет максимальные восемь налётчиков или весь мир из 25 регионов.

Директор ограничен одним Смотрителем и восемью налётчиками. Поиск пути распределяется по кругу, не чаще одного запроса за 0,25 игровой секунды; проверка модели подтверждает, что все девять акторов получают очередь. Дополнительных библиотек и отдельных GPU-текстур для противников нет. Статическая сборка занимает около 2,44 MB без сжатия; оригинальный лист ассетов, документация и тесты в неё не включены.
